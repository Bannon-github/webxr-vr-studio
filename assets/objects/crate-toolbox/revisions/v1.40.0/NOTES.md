An already-absent `normalMap` is left alone. Pin once per shared material instance. Does **not** assign `null`, `undefined`, or a texture. Does **not** clear `normalMap` on real MeshLambertMaterial / MeshPhongMaterial / MeshToonMaterial / MeshStandardMaterial / MeshPhysicalMaterial / MeshMatcapMaterial / MeshNormalMaterial (constructors assign `this.normalMap = null`). - **Why not bumpScale:** `bumpScale` can be stored by `MaterialLoader` (`if (json.bumpScale !== undefined) material.bumpScale = json.bumpScale`) even when `bumpMap` is absent, and `Material.setValues` still rejects it on a fresh MeshBasic. `refreshUniformsCommon` reads `material.bumpScale` only inside `if (material.bumpMap)`. After v1.39.0 that branch is not taken. `WebGLPrograms.js` does not read `bumpScale`. `ShaderLib.basic` does not merge `UniformsLib.bumpmap`. Deleting `bumpScale` does not change the MeshBasic refresh path or the basic program, so it is a proven no-op for this pulse.
- **Why normalMap can be own:** installed three@0.170.0 `MeshBasicMaterial.js` does not mention `normalMap`. A fresh `MeshBasicMaterial` has `normalMap === undefined` and `Object.hasOwn(material, 'normalMap') === false`. `setValues` rejects `normalMap`. `Material.copy` and `MeshBasicMaterial.copy` do not copy it. `Material.toJSON` writes `normalMap`, `normalMapType`, and `normalScale` when `normalMap` is a texture. `MaterialLoader` then assigns `material.normalMap = getTexture(json.normalMap)`, `material.normalMapType = json.normalMapType`, and `material.normalScale` from `json.normalScale` with no type check, so the JSON round-trip leaves those as own keys on a new `MeshBasicMaterial`.
- **Why the absence:** while `isMeshBasicMaterial` is true, `refreshMaterialUniforms` calls `refreshUniformsCommon`. `if (material.normalMap)` copies `material.normalMap` into `uniforms.normalMap` and copies `material.normalScale` into `uniforms.normalScale`. `ShaderLib.basic` does not merge `UniformsLib.normalmap` (lambert and later shaders do), so `uniforms.normalMap` is absent on the basic shader. `WebGLPrograms.getParameters` sets `normalMap: !!material.normalMap` and `normalMapUv` from that map; `normalMapUv` plus `normalMapTangentSpace` / `normalMapObjectSpace` enter the program cache key. `WebGLProgram` emits `#define USE_NORMALMAP` when that parameter is true. shaderID for `MeshBasicMaterial` stays `'basic'`. A leftover own `normalMap` is not the r170 MeshBasic constructor shape and changes the basic program. `delete material.normalMap` restores the absence. This pulse does not delete `normalScale`, `normalMapType`, or `displacementMap`. `displacementMap` is the next `refreshUniformsCommon` read after `normalMap`.
