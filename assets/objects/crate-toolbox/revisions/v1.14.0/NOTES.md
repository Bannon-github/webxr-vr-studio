- **Checked installed three@0.170.0:** fresh `Material` / `MeshBasicMaterial` constructors do not assign `defaultAttributeValues` (`defaultAttributeValues === undefined` and `Object.hasOwn` is false). `ShaderMaterial` assigns `this.defaultAttributeValues = { color: [1, 1, 1], uv: [0, 0], uv1: [0, 0] }`. `ShaderMaterial.copy` does not copy `defaultAttributeValues`; the copy keeps the map its constructor assigned (not a clone of the source object). `WebGLPrograms` does not read `defaultAttributeValues` (no cache-key token and no program-layer bit). `WebGLProgram` emits no `#define` for it. `WebGLBindingStates.setupVertexAttributes` reads `material.defaultAttributeValues`. When a program attribute has no geometry attribute and `materialDefaultAttributeValues !== undefined`, it looks up `materialDefaultAttributeValues[name]` and, when that value is not `undefined`, calls `gl.vertexAttrib2fv` / `gl.vertexAttrib3fv` / `gl.vertexAttrib4fv` / `gl.vertexAttrib1fv` from `value.length`.
- **Why:** A leftover ShaderMaterial-style `defaultAttributeValues` object on a color-only MeshBasic (DCC / direct assignment) is read by `WebGLBindingStates.setupVertexAttributes`. The r170 program cache key does not include that object, so a leftover `{ color: [1, 1, 1], uv: [0, 0], uv1: [0, 0] }` (or an empty `{}`) shares the cache key of a clean MeshBasic whose constructor left the property absent. When a program attribute is missing from the geometry — the color-only unused-channel strip removes `uv` / `uv1` — and the leftover map is not `undefined`, the binding state uploads a constant with `gl.vertexAttrib2fv` / `3fv` / `4fv` / `1fv`. That is Quest 3 TBDR / binding waste on a program that still matches a clean MeshBasic. An empty `{}` still enters the lookup (`{} !== undefined`) even when no name matches. Assigning `null` also enters the branch (`null !== undefined`) and then throws on the property lookup. Assigning `undefined` skips the lookup but leaves an own property, which is not the r170 MeshBasic absence. Deleting the own property restores the r170 absence and is load-time packaging. On clean procedural materials `defaultAttributeValues` is already absent, so draws, tris, and attrBytes stay unchanged vs v1.13.0. This pulse does not invent headset milliseconds. 90 Hz ship (~11.1 ms) / 72 Hz fallback are **requested**, not measured.
