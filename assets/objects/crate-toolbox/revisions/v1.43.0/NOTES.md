- **Why not specularMap:** `MeshBasicMaterial` assigns `this.specularMap = null`. Deleting that constructor null does not change `HAS_SPECULARMAP`, `specularMapUv`, or `#define USE_SPECULARMAP`. A leftover specular *texture* would matter, and `isColorOnlyUnlitBasic` already treats a truthy `specularMap` as mapped, so it is outside this color-only absence pulse.
- **Why not emissiveIntensity:** left in place in v1.42.0. `refreshUniformsCommon` reads `material.emissiveIntensity` only inside `if (material.emissive)`. A fresh MeshBasic has no `emissive`. `WebGLPrograms.js` does not read `emissiveIntensity`. `ShaderLib.basic` does not merge an emissive uniform. Same class of skip as `displacementScale` / `displacementBias`.
- **Why metalnessMap can be own:** installed three@0.170.0 `MeshBasicMaterial.js` does not mention `metalnessMap`. A fresh `MeshBasicMaterial` has `metalnessMap === undefined` and `Object.hasOwn(material, 'metalnessMap') === false`. `setValues` rejects `metalnessMap`. `Material.copy` and `MeshBasicMaterial.copy` do not copy it. `Material.toJSON` writes `metalnessMap` when it is a texture. `MaterialLoader` then assigns `material.metalnessMap = getTexture(json.metalnessMap)` with no type check, so the JSON round-trip leaves it as an own key on a new `MeshBasicMaterial`. `isColorOnlyUnlitBasic` does not treat `metalnessMap` as a map, so a planted texture still passes the color-only gate.
- **Why the absence:** `metalnessMapUv` is the next program-cache UV after `emissiveMapUv` (`array.push(parameters.metalnessMapUv)`). `WebGLPrograms.getParameters` sets `HAS_METALNESSMAP` from `!!material.metalnessMap`, `metalnessMap` from that flag, and `metalnessMapUv` from the map channel. `WebGLProgram` emits `#define USE_METALNESSMAP` and `#define METALNESSMAP_UV`. shaderID for `MeshBasicMaterial` stays `'basic'`. `meshbasic` includes `uv_pars_vertex`, which declares `metalnessMapTransform` and `vMetalnessMapUv` under `USE_METALNESSMAP`. `ShaderLib.basic` does not merge `UniformsLib.metalnessmap` (standard does). `refreshUniformsCommon` does not read `metalnessMap`. `refreshUniformsStandard` does, and `refreshMaterialUniforms` calls it only when `isMeshStandardMaterial` is true. A leftover own `metalnessMap` is not the r170 MeshBasic constructor shape and changes the basic program. `delete material.metalnessMap` restores the absence.
- **Next pin candidate (v1.44.0):** `Material.roughnessMap`. It is the next program-cache UV after `metalnessMapUv` (`array.push(parameters.roughnessMapUv)`). `MeshBasicMaterial.js` does not mention it. `MaterialLoader` assigns `material.roughnessMap = getTexture(json.roughnessMap)` with no type guard. `WebGLPrograms` sets `HAS_ROUGHNESSMAP` from `!!material.roughnessMap` and pushes `roughnessMapUv`. `WebGLProgram` emits `#define USE_ROUGHNESSMAP`. `uv_pars_vertex` (included by meshbasic) declares `roughnessMapTransform` under `USE_ROUGHNESSMAP`. `ShaderLib.basic` does not merge `UniformsLib.roughnessmap`. `refreshUniformsCommon` does not read `roughnessMap` (`refreshUniformsStandard` does, and that runs only when `isMeshStandardMaterial` is true). `MeshStandardMaterial` assigns `this.roughnessMap = null`, so this candidate is the MeshBasic absence, not the Standard constructor null.
