- **Why:** Accidental DCC / packaged GLB leftover BufferGeometry `groups` (MultiMaterial or exporter face groups) sit on color-only unlit midtone stand-ins that use a single MeshBasicMaterial. On r170 those groups do not multiply draws today, because the renderer only walks them for a material array. They are still the landmine: `BufferGeometry.copy` keeps them, and binding a material array later would issue one draw per group on a TBDR mobile GPU and confuse DCC/GLTF round-trips. Clearing to the empty r170 array keeps the color-only stand-ins on the single `drawRange` path beside the morph fence. Geometry group pin, not a draw/tri/vert change.
