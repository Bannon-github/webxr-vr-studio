- **Checked installed three@0.170.0:** the Object3D constructor assigns `this.matrixWorldNeedsUpdate = false`. `Mesh` does not override it. `updateMatrix()` composes the local matrix and assigns `this.matrixWorldNeedsUpdate = true`. `updateMatrixWorld(force)` calls `updateMatrix()` when `matrixAutoUpdate` is true, then recomputes `matrixWorld` when `this.matrixWorldNeedsUpdate || force` (and `matrixWorldAutoUpdate === true`), then assigns `this.matrixWorldNeedsUpdate = false`. `updateWorldMatrix` does **not** read or clear `matrixWorldNeedsUpdate`; when `matrixAutoUpdate` is true it calls `updateMatrix()`, which sets the flag `true`. `Object3D.copy` copies `source.matrixWorldNeedsUpdate`. `applyMatrix4` calls `updateMatrix()` when `matrixAutoUpdate` is true, so a glTF node matrix leaves the flag `true` on a live node. `WebGLRenderer.render` calls `scene.updateMatrixWorld()` when `scene.matrixWorldAutoUpdate === true`. That call passes no `force`, so `multiplyMatrices` runs only when the flag is `true`. v1.5.0 pinned `material.version` and left `matrixWorldNeedsUpdate` alone. This pulse pins leftover `true` on the 13 packed color-only visual meshes only.
- **Why:** `matrixWorldNeedsUpdate` is the Object3D world-matrix dirty flag. `updateMatrix()` sets it `true`. `updateMatrixWorld` recomputes when the flag is `true` or `force` is set, then clears the flag. The fast path inside `updateMatrixWorld` skips `multiplyMatrices` only when the flag is `false` and `force` is `false`. That skip matters for static body LOD leaves (`matrixAutoUpdate === false` from v0.45), because `updateMatrix` is not called first. A leftover `true` on a static packed color-only visual (especially after GLTF/DCC ingest or matrix writes) forces an extra world-matrix rebuild on the JS thread before the fast path can skip it. Live lid/latch/tool/fastener keep `matrixAutoUpdate === true`, so a later `updateMatrix` may set the flag `true` again; the pin is load-time only and does not lock the flag in the frame loop. On Quest 3 TBDR that load-time / first-frame rebuild is packaging waste. Pinning to `false` does not change draws, tris, or attrBytes. This pulse does not invent headset milliseconds. 90 Hz ship (~11.1 ms) / 72 Hz fallback are **requested**, not measured.
