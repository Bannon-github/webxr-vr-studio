- **Checked installed three@0.170.0:** fresh `Material` / `MeshBasicMaterial` constructors do not assign `depthPacking` (`depthPacking === undefined` and `Object.hasOwn` is false). `MeshDepthMaterial` assigns `this.depthPacking = BasicDepthPacking` and `copy` assigns `this.depthPacking = source.depthPacking`. `WebGLPrograms.getParameters` sets `useDepthPacking: material.depthPacking >= 0` and `depthPacking: material.depthPacking || 0`. `getProgramCacheKeyParameters` pushes `parameters.depthPacking`. `getProgramCacheKeyBooleans` enables program layer 13 when `parameters.useDepthPacking` is true. `WebGLProgram` emits `#define DEPTH_PACKING` plus `parameters.depthPacking` when `useDepthPacking` is true.
- **Why:** A leftover `depthPacking` number on a color-only MeshBasic (DCC / `MeshDepthMaterial.copy` bleed / direct assignment) makes `useDepthPacking` true (`material.depthPacking >= 0`). `getProgramCacheKeyParameters` pushes that number, so `BasicDepthPacking` (3200) or `RGBADepthPacking` (3201) forks the MeshBasic program cache away from the absent-material fallback `0`. A leftover `0` pushes the same numeric fallback, but `0 >= 0` still sets `useDepthPacking`, so program layer 13 forks and `WebGLProgram` emits `#define DEPTH_PACKING 0`. Assigning `null` also sets `useDepthPacking` (`null >= 0`) and leaves an own property. Deleting the own property restores the r170 absence and is load-time packaging for Quest 3 TBDR. On clean procedural materials `depthPacking` is already absent, so draws, tris, and attrBytes stay unchanged vs v1.11.0. This pulse does not invent headset milliseconds. 90 Hz ship (~11.1 ms) / 72 Hz fallback are **requested**, not measured.
