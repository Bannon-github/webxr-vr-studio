- **Checked installed three@0.170.0:** fresh `Material` / `MeshBasicMaterial` constructors do not assign `isShaderMaterial` (`isShaderMaterial === undefined` and `Object.hasOwn` is false). `MeshBasicMaterial` assigns `this.isMeshBasicMaterial = true` only. `Material.js` does not mention `isShaderMaterial`. `Material.copy` and `MeshBasicMaterial.copy` do not copy it. `ShaderMaterial` assigns `this.isShaderMaterial = true`. `ShaderMaterial.copy` does not assign `isShaderMaterial`. `ShaderMaterial.toJSON` does not write `isShaderMaterial`. `RawShaderMaterial` assigns `this.isRawShaderMaterial = true` and inherits `isShaderMaterial` (`true`, own property). `MaterialLoader` does not parse `isShaderMaterial`. `WebGLPrograms` does not read `material.isShaderMaterial`; shaderID still comes from `shaderIDs[material.type]` (`MeshBasicMaterial` → `'basic'`). `WebGLRenderer.setProgram` reads `material.isShaderMaterial` for clippingPlanes wiring, uniform re-upload, uniformsGroups UBO bind, `materialNeedsLights`, and `releaseShaderCache`. A leftover own `true` can divert those bind branches while shaderID stays `'basic'`. `WebGLMaterials.refreshMaterialUniforms` still takes the `isMeshBasicMaterial` branch first.
- **Why:** A leftover own `isShaderMaterial === true` on a color-only MeshBasic (DCC / `ShaderMaterial` flag bleed) does not change `shaderIDs[material.type]`, so `WebGLPrograms` still compiles `ShaderLib.basic` and does not take the custom shader path. It does divert `WebGLRenderer.setProgram`: clippingPlanes uniform wiring is skipped unless `clipping === true`; uniform re-upload runs when `uniformsNeedUpdate === true`; uniformsGroups UBO update/bind runs; `materialNeedsLights` becomes true when `lights === true`; program release calls `releaseShaderCache`. That split — ShaderLib `'basic'` program with shader-material bind behavior — is inconsistent Quest 3 TBDR / bind behavior. `false`, `null`, and an own `undefined` are still own properties, which is not the r170 MeshBasic absence. Assigning `false` or `true` stores an own property. Deleting the own property restores the r170 absence and is load-time packaging. On clean procedural materials `isShaderMaterial` is already absent, so draws, tris, and attrBytes stay unchanged vs v1.21.0.
