- **Checked installed three@0.170.0:** a fresh `BufferGeometry` assigns `this.attributes = {}` and has no `color` attribute. `deleteAttribute(name)` does `delete this.attributes[name]` and does not assign `null`. `hasAttribute` is `this.attributes[name] !== undefined`. `WebGLPrograms.getParameters` copies `vertexColors: material.vertexColors` and enables the vertex-color program layer only when `parameters.vertexColors` is true. `WebGLProgram` emits `#define USE_COLOR` and `attribute vec3 color` (or `attribute vec4 color` when `USE_COLOR_ALPHA`) only then. `WebGLGeometries.update` still uploads every `geometry.attributes` entry. `GLTFLoader` maps `COLOR_0` → `color`. v1.6.0 pinned `matrixWorldNeedsUpdate` and left the `color` attribute alone. This pulse deletes leftover `color` on the 13 packed color-only visual geometries only when `vertexColors === false`.
- **Why:** `WebGLPrograms` enables vertex colors only when `material.vertexColors === true`. A leftover `color` BufferAttribute on a color-only MeshBasic with `vertexColors === false` is never read by the MeshBasic shader path. `WebGLGeometries.update` still uploads every `geometry.attributes` entry, so the leftover inflates pre-upload attrBytes and GPU buffer work on Quest 3 TBDR static props. Deleting the leftover attribute is load-time packaging. On clean procedural meshes (no `color` attr) draws, tris, and attrBytes stay unchanged vs v1.6.0. A fixture with a leftover Float32 `color` may drop measured attrBytes by `count * itemSize * 4` bytes (BoxGeometry 24 verts: itemSize 3 = **288**, itemSize 4 = **384**; 3-vert groups fixture: itemSize 3 = **36**, itemSize 4 = **48**), the same documentation style as the v0.89 skin-attr fixture. This pulse does not invent headset milliseconds. 90 Hz ship (~11.1 ms) / 72 Hz fallback are **requested**, not measured.
