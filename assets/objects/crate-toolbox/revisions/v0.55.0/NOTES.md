- **Verified r170 API (do not assume):** a fresh `MeshBasicMaterial` is already `alphaHash === false` and `forceSinglePass === false` (`Material` defaults). This pulse still pins those flags on color-only unlit stand-in **materials** so packaged GLBs that set `alphaHash=true` or `forceSinglePass=true` get corrected. A deliberately wrong color-only MeshBasic is corrected when it still passes `isColorOnlyUnlitBasic`.
- **Why:** Accidental DCC / packaged GLB `alphaHash=true` forces a stochastic discard path; `forceSinglePass=true` can change multi-pass material behavior on a TBDR mobile GPU. Unlit midtone stand-ins must not pay that. Completes the remaining r170 Material boolean GPU-state fence after v0.54 clipping. Material-state fence, not a geometry pack change. Does **not** invent custom blend equations or transparent materials.
- **Scope vs v0.54 clipping pin:** v0.54 hits the **3** unique shared color-only **materials** (wood / brass / steel) with r170 clipping defaults. v0.55 hits the **same 3** unique shared color-only **materials** with r170 `alphaHash` / `forceSinglePass` defaults. Mapped / lit stay at authored / r170 Material defaults. Collider MeshBasics stay untouched (procedural colliders keep authored wireframe). Morph / interleaved skip the same pack-pipeline gate. Materials shared with a blocked collider / morph mesh skip the visual pin.
