Fail-soft packaged paths (no `lod*` groups) still run the visual pin, including the fastener. Prefer `delete material.isMeshDistanceMaterial` when the own property is present. Does **not** clear `isMeshDistanceMaterial` on real MeshDistanceMaterial (it keeps constructor `true` and constructor distance fields `map` / `alphaMap` / `displacementMap` / `displacementScale` / `displacementBias`). - **Checked installed three@0.170.0:** fresh `Material` / `MeshBasicMaterial` constructors do not assign `isMeshDistanceMaterial` (`isMeshDistanceMaterial === undefined` and `Object.hasOwn` is false). `MeshBasicMaterial` assigns `this.isMeshBasicMaterial = true` only. `Material.js` does not mention `isMeshDistanceMaterial`. `Material.copy` and `MeshBasicMaterial.copy` do not copy it. `Material.setValues` skips a key when `this[key] === undefined`, so `new MeshBasicMaterial({ isMeshDistanceMaterial: true })` warns and does not store `isMeshDistanceMaterial`. `MeshDistanceMaterial` extends `Material`. The constructor assigns `this.isMeshDistanceMaterial = true`, `this.map = null`, `this.alphaMap = null`, `this.displacementMap = null`, `this.displacementScale = 1`, and `this.displacementBias = 0`. `MeshDistanceMaterial.copy` calls `super.copy(source)`, copies `map`, `alphaMap`, `displacementMap`, `displacementScale`, and `displacementBias`, and does not assign `isMeshDistanceMaterial` (the constructor already set `true`). `MeshDistanceMaterial` has no `toJSON` override. `Material.toJSON` does not write `isMeshDistanceMaterial`. `Material.toJSON` writes `displacementScale` and `displacementBias` only when `displacementMap` is a texture, so a fresh MeshDistanceMaterial (`displacementMap` null) does not serialize those fields. `MaterialLoader` does not parse `isMeshDistanceMaterial` (it can construct `MeshDistanceMaterial` by type). shaderID still comes from `shaderIDs[material.type]`. `MeshBasicMaterial` maps to `'basic'`. `MeshDistanceMaterial` maps to `'distanceRGBA'`. When shaderID is set, vertex and fragment shaders still come from `ShaderLib`, so a leftover flag does not switch MeshBasic off `'basic'`.
- **Why this flag next:** v1.32.0 cleared `isMeshDepthMaterial`, the else-if immediately before `isMeshDistanceMaterial` in installed three@0.170.0 `WebGLMaterials.refreshMaterialUniforms`. The next leftover Material type-flag in that order is `isMeshDistanceMaterial` (`else if (material.isMeshDistanceMaterial)` calls `refreshUniformsCommon` and `refreshUniformsDistance`; then Normal, LineBasic/Dashed, Points, Sprite, Shader). Continue one flag per pulse on those same 3 MeshBasic materials. `isMeshBasicMaterial` and `type` stay. `isMeshDistanceMaterial` is **not** a `materialNeedsLights` term. A leftover own `true` on a color-only MeshBasic does not by itself make `needsLights` true while the earlier flags stay absent. Real MeshDistanceMaterial does not assign `isMeshStandardMaterial`, so it does not take `needsLights` from this flag either. Real `MeshDistanceMaterial` keeps constructor `true`. `refreshUniformsDistance` reads `properties.get(material).light` and writes `uniforms.referencePosition`, `uniforms.nearDistance`, and `uniforms.farDistance`.
- **Why the absence:** `WebGLMaterials.refreshMaterialUniforms` checks `isMeshBasicMaterial` before `isMeshDepthMaterial`. After the depth else-if, `else if (material.isMeshDistanceMaterial)` calls `refreshUniformsCommon` and `refreshUniformsDistance`. While `isMeshBasicMaterial` stays true, refresh still takes the MeshBasic branch and does not enter the distance else-if, so it does not call `refreshUniformsDistance`. A leftover own `true` is still not the r170 MeshBasic constructor shape (fresh `Material` / `MeshBasicMaterial` leave the flag absent). Real MeshDistanceMaterial keeps constructor `true` and leaves `isMeshBasicMaterial` absent, so refresh takes that distance else-if. Assigning `null`, `undefined`, `false`, or `true` stores an own property, which is not the r170 MeshBasic absence (`Object.hasOwn` stays true). Deleting the own property restores the r170 absence and is load-time packaging. On clean procedural materials `isMeshDistanceMaterial` is already absent, so draws, tris, unique verts, and attrBytes stay unchanged vs v1.32.0.
