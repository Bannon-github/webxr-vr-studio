An already-absent `emissiveMap` is left alone. Pin once per shared material instance. Does **not** assign `null`, `undefined`, or a texture. Does **not** clear `emissiveMap` on real MeshLambertMaterial / MeshPhongMaterial / MeshToonMaterial / MeshStandardMaterial / MeshPhysicalMaterial (constructors assign `this.emissiveMap = null`). - **Why not emissiveIntensity:** `MaterialLoader` assigns `material.emissiveIntensity = json.emissiveIntensity` with no type guard, even when `emissiveMap` and `emissive` are absent, and `Material.setValues` still rejects `emissiveIntensity` on a fresh MeshBasic. `refreshUniformsCommon` reads `material.emissiveIntensity` only inside `if (material.emissive)`. A fresh MeshBasic has no `emissive` (`emissive === undefined`), and `MaterialLoader` writes `emissive` only when `material.emissive !== undefined`, so that branch is not taken. `WebGLPrograms.js` does not read `emissiveIntensity`. `ShaderLib.basic` does not merge an emissive uniform. Deleting `emissiveIntensity` does not change the MeshBasic refresh path or the basic program, so it is a proven no-op for this pulse (same class as `displacementScale` / `displacementBias` after `displacementMap` is absent).
- **Why emissiveMap can be own:** installed three@0.170.0 `MeshBasicMaterial.js` does not mention `emissiveMap`. A fresh `MeshBasicMaterial` has `emissiveMap === undefined` and `Object.hasOwn(material, 'emissiveMap') === false`. `setValues` rejects `emissiveMap`. `Material.copy` and `MeshBasicMaterial.copy` do not copy it. `Material.toJSON` writes `emissiveMap` when it is a texture. `MaterialLoader` then assigns `material.emissiveMap = getTexture(json.emissiveMap)` with no type check, so the JSON round-trip leaves it as an own key on a new `MeshBasicMaterial`.
- **Why the absence:** while `isMeshBasicMaterial` is true, `refreshMaterialUniforms` calls `refreshUniformsCommon`. `if (material.emissiveMap)` copies `material.emissiveMap` into `uniforms.emissiveMap` and refreshes `emissiveMapTransform`. `ShaderLib.basic` does not merge `UniformsLib.emissivemap` (lambert, phong, toon, and standard do), so `uniforms.emissiveMap` is absent on the basic shader. `WebGLPrograms.getParameters` sets `HAS_EMISSIVEMAP` from `!!material.emissiveMap`, `emissiveMap` from that flag, and `emissiveMapUv` from the map channel. `emissiveMapUv` enters the program cache key. `WebGLProgram` emits `#define USE_EMISSIVEMAP` when that parameter is true. shaderID for `MeshBasicMaterial` stays `'basic'`. `meshbasic` includes `uv_pars_vertex`, which declares `emissiveMapTransform` and `vEmissiveMapUv` under `USE_EMISSIVEMAP`. A leftover own `emissiveMap` is not the r170 MeshBasic constructor shape and changes the basic program. `delete material.emissiveMap` restores the absence. This pulse does not delete `emissiveIntensity` or `emissive`.
- **Not the next absence pin:** `specularMap` is the next `refreshUniformsCommon` read after `emissiveMap`, but `MeshBasicMaterial` assigns `this.specularMap = null`. Deleting that constructor null does not change `HAS_SPECULARMAP`, `specularMapUv`, or `#define USE_SPECULARMAP`. A leftover specular *texture* would matter, and `isColorOnlyUnlitBasic` already treats a truthy `specularMap` as mapped, so it is outside this color-only absence pulse.
- **Next pin candidate (v1.43.0):** `Material.metalnessMap`. It is the next program-cache UV after `emissiveMapUv` (`array.push(parameters.metalnessMapUv)`). `MeshBasicMaterial.js` does not mention it. `MaterialLoader` assigns `material.metalnessMap = getTexture(json.metalnessMap)` with no type guard. `WebGLPrograms` sets `HAS_METALNESSMAP` from `!!material.metalnessMap` and pushes `metalnessMapUv`. `WebGLProgram` emits `#define USE_METALNESSMAP`. `uv_pars_vertex` (included by meshbasic) declares `metalnessMapTransform` under `USE_METALNESSMAP`. `ShaderLib.basic` does not merge `UniformsLib.metalnessmap`. `refreshUniformsCommon` does not read `metalnessMap` (`refreshUniformsStandard` does, and that runs only when `isMeshStandardMaterial` is true).
