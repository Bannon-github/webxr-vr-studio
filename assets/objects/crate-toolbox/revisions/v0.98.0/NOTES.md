- **Checked installed three@0.170.0:** the BufferAttribute constructor assigns `this.version = 0`. `Float16BufferAttribute` calls that constructor and does not override `version`, so a Float16 `position` also starts at `0`. The `needsUpdate` setter increments `version` when `value === true`. `BufferAttribute.copy` does not copy `version` (a fresh clone starts at `0`). `toJSON` does not write `version`. `WebGLAttributes.update` creates the GL buffer on first sight and stores `attribute.version`; a later call runs `updateBuffer` (`gl.bufferSubData`, then `onUploadCallback`) when the stored buffer version is less than `attribute.version`. `BufferGeometry.applyMatrix4` sets `position.needsUpdate = true`. v0.97 pinned `name` and left `version` alone, so a DCC / GLB / JSON leftover, a prior `needsUpdate`, or that matrix bake can leave a non-zero `version` on static packed color-only props before the first upload. This pulse pins the leftover. It does **not** replace attributes, typed arrays, or the geometry. It does **not** touch `name`. It does **not** touch `gpuType`. It does **not** call `setUsage`. It does **not** reassign `normalized`. It does **not** touch `onUpload` / `onUploadCallback`. It does **not** touch `updateRange` or `updateRanges`. Mapped / lit stay authored because `isColorOnlyUnlitBasic` is false when `map` / `lightMap` / `aoMap` / `specularMap` / `alphaMap` / `envMap` is set.
- **Why:** GLTF / DCC ingest, JSON round-trips, and in-place `needsUpdate` / `applyMatrix4` paths can leave a non-zero `version` on attributes and the index of static color-only props. `WebGLAttributes.update` re-uploads (`gl.bufferSubData`) when the stored buffer version is less than `attribute.version`. Pinning to `0` before that comparison is load-time L3 packaging only: no draw / tri / attrBytes change; it avoids extra TBDR buffer work on Quest 3 static props. These stand-ins keep float-typed position (+ index); `vertexColors` stays false (v0.57) and unused color/uv/normal/skin attrs are already stripped on the clean path. Pinning `version === 0` restores the r170 constructor default. Direct assignment does not go through `needsUpdate`, so the pin does not increment. Pre-upload draws / tris / verts / attrBytes on clean procedural meshes are unchanged vs v0.97. This pulse does not invent headset milliseconds.
