- **Why not anisotropyMap:** it is the next program-cache UV after `roughnessMapUv` (`array.push(parameters.anisotropyMapUv)`), but `HAS_ANISOTROPYMAP` is `(material.anisotropy > 0) && !!material.anisotropyMap`. A fresh MeshBasic has `anisotropy === undefined`, so `anisotropy > 0` is false. Deleting a leftover `anisotropyMap` while anisotropy is absent does not change `anisotropyMapUv` or `#define USE_ANISOTROPYMAP`. `MeshPhysicalMaterial` assigns `this.anisotropyMap = null` and keeps anisotropy at 0. The same scalar gate rejects `clearcoatMap` / `clearcoatNormalMap` / `clearcoatRoughnessMap` (`clearcoat > 0`), `iridescenceMap` / `iridescenceThicknessMap` (`iridescence > 0`), and `sheenColorMap` / `sheenRoughnessMap` (`sheen > 0`).
- **Why not specularMap:** `MeshBasicMaterial` assigns `this.specularMap = null`. Deleting that constructor null does not change `HAS_SPECULARMAP`, `specularMapUv`, or `#define USE_SPECULARMAP`. A leftover specular *texture* would matter, and `isColorOnlyUnlitBasic` already treats a truthy `specularMap` as mapped, so it is outside this color-only absence pulse.
- **Why not emissiveIntensity:** left in place in v1.42.0. `refreshUniformsCommon` reads `material.emissiveIntensity` only inside `if (material.emissive)`. A fresh MeshBasic has no `emissive`. `WebGLPrograms.js` does not read `emissiveIntensity`. `ShaderLib.basic` does not merge an emissive uniform. Same class of skip as `displacementScale` / `displacementBias`.
- **Why roughnessMap can be own:** installed three@0.170.0 `MeshBasicMaterial.js` does not mention `roughnessMap`. A fresh `MeshBasicMaterial` has `roughnessMap === undefined` and `Object.hasOwn(material, 'roughnessMap') === false`. `setValues` rejects `roughnessMap`. `Material.copy` and `MeshBasicMaterial.copy` do not copy it. `Material.toJSON` writes `roughnessMap` when it is a texture. `MaterialLoader` then assigns `material.roughnessMap = getTexture(json.roughnessMap)` with no type check, so the JSON round-trip leaves it as an own key on a new `MeshBasicMaterial`. `isColorOnlyUnlitBasic` does not treat `roughnessMap` as a map, so a planted texture still passes the color-only gate.
- **Why the absence:** `roughnessMapUv` is the next program-cache UV after `metalnessMapUv` (`array.push(parameters.roughnessMapUv)`). `WebGLPrograms.getParameters` sets `HAS_ROUGHNESSMAP` from `!!material.roughnessMap`, `roughnessMap` from that flag, and `roughnessMapUv` from the map channel. `WebGLProgram` emits `#define USE_ROUGHNESSMAP` and `#define ROUGHNESSMAP_UV`. shaderID for `MeshBasicMaterial` stays `'basic'`. `meshbasic` includes `uv_pars_vertex`, which declares `roughnessMapTransform` and `vRoughnessMapUv` under `USE_ROUGHNESSMAP`. `ShaderLib.basic` does not merge `UniformsLib.roughnessmap` (standard does). `refreshUniformsCommon` does not read `roughnessMap`. `refreshUniformsStandard` does, and `refreshMaterialUniforms` calls it only when `isMeshStandardMaterial` is true. A leftover own `roughnessMap` is not the r170 MeshBasic constructor shape and changes the basic program. `delete material.roughnessMap` restores the absence.
- **Next pin candidate (v1.45.0):** `Material.specularColorMap`. After the scalar-gated maps and the MeshBasic constructor-null `specularMap`, `specularColorMapUv` is the next program-cache UV (`array.push(parameters.specularColorMapUv)`). `MeshBasicMaterial.js` does not mention it. A fresh MeshBasic leaves it absent. `Material.toJSON` writes it when it is a texture. `MaterialLoader` assigns `material.specularColorMap = getTexture(json.specularColorMap)` with no type guard. `WebGLPrograms` sets `HAS_SPECULAR_COLORMAP` from `!!material.specularColorMap` and pushes `specularColorMapUv`. `WebGLProgram` emits `#define USE_SPECULAR_COLORMAP`. `uv_pars_vertex` (included by meshbasic) declares `specularColorMapTransform` under `USE_SPECULAR_COLORMAP`. `ShaderLib.basic` does not declare `specularColorMap` (`ShaderLib.physical` does). `refreshUniformsCommon` does not read it (`refreshUniformsPhysical` does, and that runs only when `isMeshPhysicalMaterial` is true). `MeshPhysicalMaterial` assigns `this.specularColorMap = null`, so this candidate is the MeshBasic absence, not the Physical constructor null. `isColorOnlyUnlitBasic` does not treat `specularColorMap` as a map. Deleting a planted texture changes the basic program; deleting the Physical constructor null is not this pulse.
