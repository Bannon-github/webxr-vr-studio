# crate-toolbox v1.3.0

L3 packaging/perf UPGRADE on the same `objectId`. No GLB. Not a new layer.

- After v1.2.0 pinned leftover Material `name` to the r170 constructor default empty string (`material.name === ''`) on the **3** shared color-only MeshBasic materials (wood / brass / steel), **`pinColorOnlyUnlitBasicMeshName` / `pinColorOnlyVisualMeshName` pin leftover Mesh / Object3D `name` to the r170 constructor default empty string (`mesh.name === ''`)** on packed color-only unlit MeshBasic visual meshes (body LOD leaves + lid/latch/tool + fastener). Procedural create runs the visual helper after `pinColorOnlyVisualMaterialName`. Packaged ingest pins after the same detect (does not hex-dedupe; does not invent meshes). Fail-soft packaged paths (no `lod*` groups) still run the visual pin, including the fastener. Assign `mesh.name = ''` in place only when it is not already `''` and the name is not reserved. Reserved names stay: `lidMesh`, `latchMesh`, `fastenerMesh`, and any `collider_*` mesh name. An already-empty name is left as-is. Does **not** replace the mesh, the material, the geometry, the attributes, or the typed arrays. Does **not** touch Material `name` (v1.2.0 material-name-empty stays). Does **not** touch Material `userData` (v1.1.0 material-userData-empty stays). Does **not** touch prior material program-cache / flag pins. Does **not** touch BufferGeometry `userData` (v1.0.0 geometry-userData-empty stays). Does **not** touch BufferGeometry `name` (v0.99 geometry-name-empty stays). Does **not** touch Mesh / Object3D `userData` (studio metadata: collider, lod, parts, fastener, and the rest stay). Does **not** touch BufferAttribute `version` / `name` / `gpuType` / `normalized` / `usage` / `updateRange` / `updateRanges` / `onUpload` / `onUploadCallback`. Does **not** touch geometry `boundingBox` / `boundingSphere` or Mesh `boundingSphere`. Does **not** delete `skinIndex` / `skinWeight`. Does **not** touch `drawRange` / `groups` / `morphAttributes` / Mesh morph targets / Object3D `animations`. Does **not** enable shadows. Does **not** pin `mesh.visible`. Does **not** change `frustumCulled` (v0.50 stays true). Does **not** change `matrixAutoUpdate` (v0.45 freeze stays). Named meshes `lidMesh` / `latchMesh` / `fastenerMesh` kept. The v0.37–v1.2.0 pipeline stays intact; v1.3.0 adds the Mesh `name` pin after the material-name pin.
- **Checked installed three@0.170.0:** the Object3D constructor assigns `this.name = ''`. `Mesh` does not override `name`. `Object3D.toJSON` writes `object.name` only when `this.name !== ''`. `Object3D.copy` copies `source.name`. `ObjectLoader.parseObject` assigns `object.name = data.name` when `data.name !== undefined`. Stock `GLTFLoader` `loadMesh` assigns `mesh.name = parser.createUniqueName(meshDef.name || ('mesh_' + meshIndex))`, then `_loadNodeShallow` assigns `node.name` from `createUniqueName(nodeDef.name)` when the node has a name. When the node has one object, that object is the mesh, so the node name replaces the primitive name. `WebGLRenderer` does not read `mesh.name` (no `.name` access). `WebGLPrograms.getParameters` copies `shaderName: material.name`, not the mesh name, so a leftover mesh name does not fork the program cache or change the draw. v1.2.0 pinned `material.name` and left `mesh.name` alone, so DCC / glTF node and mesh names can still sit on the packed color-only visuals. This pulse pins the leftover unless the name is reserved.
- **Why:** Stock GLTFLoader writes mesh and node names onto `mesh.name`. After the v1.2.0 material-name pin, those strings can still sit on static packed color-only MeshBasics. `WebGLRenderer` does not key draws on `mesh.name`. Clearing non-reserved names to `''` is load-time L3 packaging only: no draw / tri / attrBytes change. Studio-named interactables (`lidMesh`, `latchMesh`, `fastenerMesh`) and `collider_*` hulls stay named so pick / activity lookup keeps working. Pre-upload draws / tris / verts / attrBytes on clean procedural meshes are unchanged vs v1.2.0. This pulse does not invent headset milliseconds.
- **Scope vs v1.2.0 material-name pin:** v1.2.0 hits the **3** unique color-only MeshBasic **materials** so each `material.name === ''`. v1.3.0 hits the **13** packed color-only visual **meshes** and clears non-reserved `mesh.name`. Measured unique materials stay **3**. material-name-empty stays **3**. Fresh r170 `Object3D` already uses `name = ''`. Mapped / lit `mesh.name` stays authored. Interleaved meshes stay authored. A mesh whose material is shared with a blocked collider or interleaved mesh, or whose geometry is shared with a collider, an interleaved mesh, or a mapped / lit mesh, skips the visual pin. Color-only leftover non-empty `mesh.name` is pinned unless it is reserved: that leftover is the pulse.
- **Gate (same `isColorOnlyUnlitBasic` as `pinColorOnlyVisualMaterialName`):** only color-only unlit MeshBasic. Skip `userData.collider` / `collider_*` names. Skip mapped / lit. Skip interleaved geos. Skip materials shared with a blocked collider / interleaved mesh. Skip geometries shared with a collider, an interleaved mesh, or a mapped / lit mesh. Keep `lidMesh` / `latchMesh` / `fastenerMesh` even when the mesh is otherwise eligible.
- **Measurement rule:** `userData.lod.stats.attrBytes` is the **pre-upload** CPU envelope. Assigning `mesh.name = ''` does not change attribute byte length. `mesh-name-empty` counts packed color-only visual meshes (LOD leaves + fastener) whose `mesh.name === ''` after the pin. Reserved named meshes are not forced empty and are not part of that count. `material-name-empty` still counts unique color-only MeshBasics whose `material.name === ''`. `countGroupStats` does not read `mesh.name`, so the pin does not change the draws/tris/verts/attrBytes envelope.
