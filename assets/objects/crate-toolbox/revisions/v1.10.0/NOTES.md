# crate-toolbox v1.10.0

L3 packaging/perf UPGRADE on the same `objectId`. No GLB. Not a new layer.

- After v1.9.0 stripped leftover `normal` / `uv` / `uv1` / `uv2` / `uv3` / `tangent` so none of those channels remain on the **13** packed color-only unlit MeshBasic visual geometries (unusedAttributes-absent **13**; onUpload-release **13**; colorAttribute-absent **13**; matrixWorldNeedsUpdate-false **13**; material-version-zero **3**; mesh-userData-empty **13**; mesh-name-empty **10**), **`pinColorOnlyUnlitBasicIndirect` / `pinColorOnlyVisualIndirect` pin leftover BufferGeometry `indirect` to the r170 constructor default `null` (`geometry.indirect === null`)** on those same **13** geometries (body LOD leaves + lid/latch/tool + fastener). Procedural create runs the visual helper after `pinColorOnlyVisualUnusedAttributes`. Packaged ingest pins after the same detect (does not hex-dedupe; does not invent meshes). Fail-soft packaged paths (no `lod*` groups) still run the visual pin, including the fastener. Call `setIndirect(null)` only when `indirect` is not already `null`. Does **not** invent a replacement buffer. Does **not** call `delete` on unrelated fields. Does **not** re-run the unused-channel strip (v1.9.0 unusedAttributes-absent stays). Does **not** touch `onUpload` / `onUploadCallback` (v1.8.0 onUpload-release stays). Does **not** touch `color` (v1.7.0 colorAttribute-absent stays). Does **not** touch Mesh `matrixWorldNeedsUpdate` (v1.6.0 stays). Does **not** change `matrixAutoUpdate` or `matrixWorldAutoUpdate`. Does **not** touch BufferGeometry `userData` / `name`. The v0.37–v1.9.0 pipeline stays intact; v1.10.0 adds the indirect pin after the unused-channel pin.
- **Checked installed three@0.170.0:** the BufferGeometry constructor assigns `this.indirect = null`. `setIndirect(indirect)` assigns `this.indirect = indirect` and returns `this`. `getIndirect()` returns `this.indirect`. `BufferGeometry.copy` does not copy `indirect`, so a cloned merge survivor stays at the constructor `null` unless something assigns it later. In `src/renderers/common/Geometries.js`, when `renderObject.geometry.indirect !== null`, the renderer calls `updateAttribute(indirect, AttributeType.INDIRECT)`.
- **Why:** Leftover indirect storage on a color-only static MeshBasic is not multi-draw / BatchedMesh indexing, but the common renderer still uploads and binds it when `indirect !== null`. Clearing it to `null` is load-time packaging for Quest 3 TBDR. On clean procedural meshes `indirect` is already the constructor `null`, so draws, tris, and attrBytes stay unchanged vs v1.9.0. This pulse does not invent headset milliseconds. 90 Hz ship (~11.1 ms) / 72 Hz fallback are **requested**, not measured.
- **Scope vs v1.9.0 unused-channel strip:** v1.9.0 hits the **13** packed color-only visual **geometries** and deletes leftover `normal` / `uv` / `uv1` / `uv2` / `uv3` / `tangent` (unusedAttributes-absent **13**). v1.10.0 hits those same **13** geometries and pins leftover `indirect` to `null` when it is not already `null`. Measured unique materials stay **3**. unusedAttributes-absent stays **13**. onUpload-release stays **13**. colorAttribute-absent stays **13**. matrixWorldNeedsUpdate-false stays **13**. material-version-zero stays **3**. mesh-name-empty stays **10**. mesh-userData-empty stays **13**. Mapped / lit / interleaved keep authored `indirect`. Collider meshes stay untouched. A mesh whose material is shared with a blocked collider or interleaved mesh, or whose geometry is shared with a collider, an interleaved mesh, or a mapped / lit mesh, skips the visual pin.
