- **Checked installed three@0.170.0:** `BufferAttribute` declares `onUploadCallback() {}` on the prototype. The constructor does not assign an own `onUploadCallback`. `onUpload(callback)` assigns `this.onUploadCallback = callback` and does not null `.array` and does not bump `version`. `BufferAttribute.copy` does not copy `onUploadCallback`. `WebGLAttributes.createBuffer` copies `attribute.array` into a local, calls `gl.bufferData(bufferType, array, usage)`, then calls `attribute.onUploadCallback()`. `updateBuffer` calls `onUploadCallback` after `gl.bufferSubData`. v1.7.0 stripped leftover `color` and left `onUpload` / `onUploadCallback` alone. This pulse pins the v0.43 release hook on the remaining attributes of the 13 packed color-only visual geometries.
- **Why:** The callback runs after the GPU upload. A leftover non-release callback, or the r170 empty prototype method, skips the Quest 3 CPU-array release. Static packed color-only props then keep their Float16 / Uint16 CPU arrays after upload on a TBDR headset. `BufferAttribute.copy` drops the hook, so DCC / glTF / JSON / copy paths fall back to the empty prototype method or leave a different callback. The pin installs the release hook only. It does not null `.array` and does not recompute bounds. On clean procedural meshes draws, tris, and attrBytes stay unchanged vs v1.7.0. This pulse does not invent headset milliseconds. 90 Hz ship (~11.1 ms) / 72 Hz fallback are **requested**, not measured.
