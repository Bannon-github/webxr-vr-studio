- **Verified r170 API (three@0.170.0 in this repo; do not assume):** the BufferGeometry constructor assigns `this.drawRange = { start: 0, count: Infinity }` (`REVISION` 170). `setDrawRange(start, count)` assigns `this.drawRange.start` and `this.drawRange.count` (it does not replace the object; it throws when `drawRange` is missing). `BufferGeometry.copy` copies `start` and `count` onto the destination's existing object. r170 `WebGLRenderer.renderBufferDirect` reads `geometry.drawRange` (`drawStart = drawRange.start * rangeFactor`, `drawEnd = (drawRange.start + drawRange.count) * rangeFactor`) and intersects a group range only when that render item's `group` is non-null. `projectObject` pushes one item with `group = null` when the material is not an array. - **Why:** Accidental DCC / packaged GLB leftover BufferGeometry `drawRange` (a partial `start` / `count`) sits on color-only unlit midtone stand-ins that use a single MeshBasicMaterial. On r170 that span is the draw the Quest Browser issues, because the renderer only intersects `groups` when the material is an array. A leftover range silently clips or under-draws the prop. Pinning the r170 default keeps the color-only stand-ins on the full index/position span beside the groups fence. Geometry draw-span pin, not a draw/tri/vert change.
