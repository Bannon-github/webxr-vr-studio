- **Checked installed three@0.170.0:** the BufferAttribute constructor is `(array, itemSize, normalized = false)` and assigns `this.normalized = normalized`. Omitting the argument leaves `normalized === false`. `Float16BufferAttribute` forwards its third argument, so an omitted Float16 flag is also `false`. `WebGLAttributes.createBuffer` does not read `normalized` (it passes `usage` to `gl.bufferData`). `WebGLBindingStates.setupVertexAttributes` reads `geometryAttribute.normalized` and passes it to `gl.vertexAttribPointer`. WebGL requires `normalized` to be false for `FLOAT` and `HALF_FLOAT`. v0.94 pinned `usage` and left `normalized` alone, so a DCC / GLB leftover `normalized === true` can survive when the upload hook skips the geometry. This pulse pins the leftover. It does **not** replace attributes, typed arrays, or the geometry. It does **not** call `setUsage`. It does **not** touch `updateRange` or `updateRanges`. It does **not** touch geometry bounds or Mesh `boundingSphere`. It does **not** change `frustumCulled`. Do **not** delete `skinIndex` / `skinWeight`. Do **not** touch `drawRange`. Do **not** touch `groups`. Do **not** touch `morphAttributes` / `morphTargetsRelative`. Do **not** touch Mesh morph-target properties. Do **not** touch Object3D `animations`. Mapped / lit stay authored because `isColorOnlyUnlitBasic` is false when `map` / `lightMap` / `aoMap` / `specularMap` / `alphaMap` / `envMap` is set.
- **Why:** Accidental DCC / exporter leftover `normalized === true` on static packed color-only Float16 / Float32 `position` (or the index) tells `gl.vertexAttribPointer` to normalize values that are already object-space positions. On Quest 3 that flag is invalid for `FLOAT` / `HALF_FLOAT` and breaks the TBDR draw. These stand-ins keep position (+ index); `vertexColors` stays false (v0.57) and unused color/uv/normal/skin attrs are already stripped on the clean path. Pinning `normalized === false` restores the r170 constructor default. Pre-upload draws / tris / verts / attrBytes on clean procedural meshes are unchanged vs v0.94. This pulse does not invent headset milliseconds.

Color-only leftover `normalized !== false` is pinned rather than kept: that leftover is the pulse.
