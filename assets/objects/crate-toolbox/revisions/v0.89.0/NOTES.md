- **Verified r170 API (three@0.170.0 in this repo; do not assume):** `WebGLPrograms.getParameters` sets `skinning: object.isSkinnedMesh === true` (`REVISION` 170). `WebGLProgram` emits `#define USE_SKINNING` only when that parameter is true, and only then declares `attribute vec4 skinIndex` and `attribute vec4 skinWeight`. `skinning_pars_vertex` / `skinning_vertex` read `skinWeight` and `bindMatrix` only under `USE_SKINNING`. A plain `Mesh` + `MeshBasicMaterial` never sets `isSkinnedMesh`, so MeshBasic does not read those attributes. `WebGLGeometries.update` still walks every `geometry.attributes` entry and uploads it, so leftover `skinIndex` / `skinWeight` inflate the pre-upload attrBytes envelope and the GPU buffer even though the color-only program never samples them. r170 `GLTFLoader` `ATTRIBUTES` maps `JOINTS_0` → `skinIndex` and `WEIGHTS_0` → `skinWeight`. It constructs a `SkinnedMesh` only when `meshDef.isSkinnedMesh` is true (the node has a skin). `SkinnedMesh.applyBoneTransform` reads `geometry.attributes.skinIndex` together with `bindMatrix`. The landmine is a later SkinnedMesh / GLTF skin round-trip, or dead attribute upload, on stand-ins that are plain `Mesh` + MeshBasic. This pulse deletes the leftover attributes.
