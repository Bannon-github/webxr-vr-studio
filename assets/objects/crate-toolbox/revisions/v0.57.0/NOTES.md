- **Verified r170 API (do not assume):** a fresh `MeshBasicMaterial` is already `vertexColors === false` (`Material` default). This pulse still pins that default on color-only unlit stand-in **materials** so packaged GLBs that leave `vertexColors = true` leftovers get corrected. A deliberately wrong color-only MeshBasic is corrected when it still passes `isColorOnlyUnlitBasic`. `stripUnusedColorOnlyAttributes` already drops `color` when `!material.vertexColors` — pinning false makes that strip reliably apply after DCC leftovers.
- **Why:** Accidental DCC / packaged GLB `vertexColors = true` leftovers force a color-attribute shader variant on a TBDR mobile GPU even when maps are absent (still passes `isColorOnlyUnlitBasic`) and keep a `color` attribute that the strip helper would otherwise drop. Pinning `vertexColors = false` keeps the Quest-safe opaque unlit contract. Material-state fence, not a geometry pack change. Does **not** invent custom shaders, transparent materials, or enable vertex colors elsewhere.
- **Scope vs v0.56 NormalBlending companions pin:** v0.56 hits the **3** unique shared color-only **materials** (wood / brass / steel) with r170 NormalBlending factor/equation companions. v0.57 hits the **same 3** unique shared color-only **materials** with r170 `vertexColors = false`. Mapped / lit stay at authored / r170 Material defaults. Collider MeshBasics stay untouched (procedural colliders keep authored wireframe). Morph / interleaved skip the same pack-pipeline gate. Materials shared with a blocked collider / morph mesh skip the visual pin.
