- **Checked installed three@0.170.0:** fresh `Material` / `MeshBasicMaterial` constructors do not assign `linewidth` (`linewidth === undefined` and `Object.hasOwn` is false). `MeshBasicMaterial` assigns `this.wireframeLinewidth = 1` only. `Material.js` does not assign `this.linewidth` in the constructor. `Material.copy` and `MeshBasicMaterial.copy` do not copy `linewidth` (`MeshBasicMaterial.copy` copies `wireframeLinewidth`). `Material.setValues` skips a key when `this[key] === undefined`, so `new MeshBasicMaterial({ linewidth })` warns and does not store `linewidth`. `ShaderMaterial` assigns `this.linewidth = 1`. `ShaderMaterial.copy` does not copy `linewidth`. `Material.toJSON` writes `linewidth` only when `this.linewidth !== undefined && this.linewidth !== 1`. `LineBasicMaterial` assigns `this.linewidth = 1` and `LineBasicMaterial.copy` assigns `this.linewidth = source.linewidth`. `LineDashedMaterial` extends `LineBasicMaterial` and keeps that constructor value through `super()` / `super.copy`. `MaterialLoader` assigns `material.linewidth = json.linewidth` when `json.linewidth !== undefined`. `WebGLRenderer.renderBufferDirect` reads `material.linewidth` only on the `object.isLine` branch (`let lineWidth = material.linewidth`; undefined falls back to 1) and calls `state.setLineWidth`. The `object.isMesh` branch reads `material.wireframeLinewidth` when `wireframe === true` and does not read `material.linewidth`. `WebGLState.setLineWidth` calls `gl.lineWidth` when `lineWidthAvailable` (r170 treats WebGL version >= 1.0, including WebGL 2, as available) and reset calls `gl.lineWidth(1)`. `WebGLShadowMap` copies `result.linewidth = material.linewidth`.
- **Why:** WebGL 2 (Quest Browser) only accepts line width 1. A non-1 `gl.lineWidth` is an `INVALID_VALUE` and is unused. Crate visuals are `Mesh`, so `WebGLRenderer` does not consult `material.linewidth` on their draw at all (it consults `wireframeLinewidth` only when `wireframe === true`). A leftover own `linewidth` on a color-only MeshBasic — from `MaterialLoader` or a direct assign, including `2`, `0`, `1`, `null`, or an own `undefined` — is unused packaging waste / inconsistent authored state. Assigning `null`, `undefined`, `0`, or `1` stores an own property, which is not the r170 MeshBasic absence (`Object.hasOwn` stays true). Deleting the own property restores the r170 absence and is load-time packaging. On clean procedural materials `linewidth` is already absent, so draws, tris, unique verts, and attrBytes stay unchanged vs v1.23.0. This pulse does not invent headset milliseconds. 90 Hz ship (~11.1 ms) / 72 Hz fallback are **requested**, not measured.
