# crate-toolbox v1.5.0

L3 packaging/perf UPGRADE on the same `objectId`. No GLB. Not a new layer.

- After v1.4.0 pinned leftover Mesh / Object3D `userData` to the r170 constructor default empty plain object (`mesh.userData` is a fresh `{}`) on the **13** packed color-only unlit MeshBasic visual meshes (mesh-userData-empty **13**; root / tool Group / collider studio userData preserved; mesh-name-empty **10**), **`pinColorOnlyUnlitBasicMaterialVersion` / `pinColorOnlyVisualMaterialVersion` pin leftover Material `version` to the r170 constructor default `0` (`material.version === 0`)** on the **3** shared color-only MeshBasic materials (wood / brass / steel) those visuals use. Procedural create runs the visual helper after `pinColorOnlyVisualMeshUserData`. Packaged ingest pins after the same detect (does not hex-dedupe; does not invent materials). Fail-soft packaged paths (no `lod*` groups) still run the visual pin, including the fastener. Assign `material.version = 0` in place only when it is not already `0`. Do not call `material.needsUpdate = true` (that increments `version`). Direct assignment does not go through `needsUpdate`. Pin once per shared material instance. Does **not** replace the material, the mesh, the geometry, the attributes, or the typed arrays. Does **not** invent materials. Does **not** touch Material `name` (v1.2.0 material-name-empty stays). Does **not** touch Material `userData` (v1.1.0 material-userData-empty stays). Does **not** touch Mesh / Object3D `userData` (v1.4.0 mesh-userData-empty stays). Does **not** touch Mesh / Object3D `name` (v1.3.0 mesh-name-empty stays; reserved names `lidMesh` / `latchMesh` / `fastenerMesh` and any `collider_*` stay). Does **not** touch BufferGeometry `userData` / `name`. Does **not** touch BufferAttribute fields, prior material program-cache / flag pins, bounds, morphs, animations, shadows, `frustumCulled`, `matrixAutoUpdate`, or `mesh.visible`. Does **not** enable shadows. Named meshes `lidMesh` / `latchMesh` / `fastenerMesh` kept. The v0.37–v1.4.0 pipeline stays intact; v1.5.0 adds the Material `version` pin after the mesh-userData pin.
- **Checked installed three@0.170.0:** the Material constructor assigns `this.version = 0`. The `needsUpdate` setter increments `version` when `value === true`. The `alphaTest` setter also increments `version` when the test crosses zero. `Material.copy` does not copy `version`. `Material.toJSON` does not write `material.version` (`metadata.version` 4.6 is the JSON format version). `WebGLRenderer.setProgram` sets `needsProgramChange` and stores `materialProperties.__version = material.version` when `material.version !== materialProperties.__version`, then calls `getProgram`, which builds parameters via `WebGLPrograms.getParameters`. `getProgramCacheKey` does not include `material.version`, so a leftover number does not fork a second program. v1.4.0 pinned `mesh.userData` and left `material.version` alone. This pulse pins leftover non-zero `material.version` on the three shared color-only MeshBasics only.
- **Why:** `material.version` is the Material dirty counter. `needsUpdate = true` increments it, and the `alphaTest` setter increments it when the test crosses zero. `WebGLRenderer.setProgram` treats `material.version !== materialProperties.__version` as `needsProgramChange` and calls `getProgram`, which allocates program parameters via `WebGLPrograms.getParameters` even when `getProgramCacheKey` ignores `material.version`. A leftover non-zero `material.version` on a static packed color-only MeshBasic does not describe a pending property change. On Quest 3 TBDR that load-time parameter rebuild is packaging waste. Pinning to `0` before first render stores the constructor default in `__version` on the unavoidable first sight and does not change draws, tris, or attrBytes. Direct assignment does not increment. This pulse does not invent headset milliseconds. 90 Hz ship (~11.1 ms) / 72 Hz fallback are **requested**, not measured.
- **Scope vs v1.4.0 mesh-userData pin:** v1.4.0 hits the **13** packed color-only visual **meshes** and clears leftover `mesh.userData` (mesh-userData-empty **13**). v1.5.0 hits the **3** shared color-only MeshBasic **materials** those visuals use and pins leftover `material.version` to `0`. Fresh r170 `Material` already uses `version = 0`. Mapped / lit `material.version` stays authored. Interleaved meshes stay authored. A mesh whose material is shared with a blocked collider or interleaved mesh, or whose geometry is shared with a collider, an interleaved mesh, or a mapped / lit mesh, skips the visual pin. Color-only leftover non-zero `material.version` is pinned: that leftover is the pulse.
