- **Verified r170 API (do not assume):** a fresh `Mesh` is already `renderOrder === 0` (`Object3D` default; `REVISION` 170). This pulse still pins that default on color-only unlit stand-in **meshes** so packaged GLBs that leave non-zero `renderOrder` leftovers get corrected. A deliberately wrong color-only Mesh (`renderOrder = 2`) is corrected when it still passes `isColorOnlyUnlitBasic`. Do not force a non-zero renderOrder. Do not pin `mesh.visible`.
- **Why:** Accidental DCC / packaged GLB non-zero `renderOrder` leftovers force separate transparent/opaque sort buckets and can break batching / increase draw overhead on a TBDR mobile GPU even when materials are already Quest-safe opaque unlit stand-ins (still passes `isColorOnlyUnlitBasic`). Pinning r170 Object3D default `0` keeps the cheap default path. Mesh-state fence, not a geometry pack change. Does **not** invent custom shaders, transparent materials, or force a non-zero renderOrder.
- **Scope vs v0.59 shadowSide pin:** v0.59 hits the **3** unique shared color-only **materials** with r170 `shadowSide = null`. v0.60 hits the **13** packed color-only visual **meshes** with r170 `renderOrder = 0` (same mesh family as v0.49 shadow flags / v0.50 frustumCulled). Mapped / lit stay at authored / r170 Mesh defaults. Collider meshes stay untouched. Morph / interleaved skip the same pack-pipeline gate. Materials shared with a blocked collider / morph mesh skip the visual pin.
- **Gate (same as pack pipeline):** only color-only unlit MeshBasic. Skip `userData.collider` / `collider_*` names. Skip mapped / lit. Skip morph / interleaved geos (conservative). Skip materials shared with a blocked collider / morph mesh.
