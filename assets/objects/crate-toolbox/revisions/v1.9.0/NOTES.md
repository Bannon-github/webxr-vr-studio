- **Checked installed three@0.170.0:** `WebGLProgram` prefix always emits `attribute vec3 normal` and `attribute vec2 uv`. `uv1` / `uv2` / `uv3` / `tangent` are behind `USE_UV1` / `USE_UV2` / `USE_UV3` / `USE_TANGENT`, which stay off without maps (`vertexTangents` needs a tangent attribute plus a normal map or anisotropy). `meshbasic.glsl.js` reads `normal` only inside `#if defined ( USE_ENVMAP ) || defined ( USE_SKINNING )`. `uv_vertex.glsl.js` reads `uv` only under `#if defined( USE_UV ) || defined( USE_ANISOTROPY )`. Color-only MeshBasic does not enable those defines. `WebGLGeometries.update` still walks every `geometry.attributes` entry and uploads it. `deleteAttribute(name)` does `delete this.attributes[name]` and does not assign `null`. `GLTFLoader` maps `NORMAL` → `normal`, `TANGENT` → `tangent`, `TEXCOORD_0` → `uv`, `TEXCOORD_1` → `uv1`, `TEXCOORD_2` → `uv2`, `TEXCOORD_3` → `uv3`.
- **Why:** Leftover DCC channels on a color-only MeshBasic are never sampled by that program, but `WebGLGeometries.update` still uploads them. On Quest 3 TBDR that is CPU/GPU attribute-upload waste. The v0.40 pack path already strips these channels after weld. Fail-soft ingest (no `lod*` groups) does not enter that helper for body/lid/latch/tool, which is why color (v1.7.0) and onUpload (v1.8.0) needed their own visual pins. The same gap exists for `normal` / `uv` / `tangent`. On clean procedural meshes those channels are already absent, so draws, tris, and attrBytes stay unchanged vs v1.8.0. This pulse does not invent headset milliseconds. 90 Hz ship (~11.1 ms) / 72 Hz fallback are **requested**, not measured.
